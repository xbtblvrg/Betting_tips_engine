# Public Polymarket reference ingestion

`reference_polymarket.py` is an isolated, opt-in read-only adapter. It uses anonymous public GETs, archives complete raw response bytes before parsing, and records exact URL, HTTP status, timestamps, SHA-256, byte count and request duration. Failed or oversized reads retain their bounded prefix with `body_complete=false`; that prefix is never presented as complete evidence. No credentials, orders, sports-model changes, Stake quote substitution or automatic probability blend are implemented.

The adapter supports a single exact upcoming full-game binary Winner market per event. Matching requires both full team names, league, ordered sides, unique sports-game identity and exact UTC start. Other market families, ambiguous identities and unsupported fee formulas produce explicit reasons. The caller supplies independently verified sports games; the adapter does not authenticate arbitrary caller-provided schedule rows. Settlement descriptions remain separately hash-pinned. All observations currently have `comparable_to_sportsbook=false` and `usable_for_automatic_blend=false`: a prediction-market half-dollar tie/cancellation payout has not been proved equivalent to the sportsbook refund contract.

Both complete outcome books are retained, including bids, asks, timestamps, sizes, minimum shares and tick size. Calculations inspect every bounded level and report observed spread/depth, fee-adjusted buy cost and sell proceeds, with insufficient-depth and minimum-share reasons. Fees come from each market's explicit `feesEnabled` and supported `feeSchedule` fields; estimates are unrounded, not guaranteed execution prices. The normalized paired midpoint is a price index, never an independently calibrated sports probability or a no-vig probability claim.

The bounded network interface has no retries, follows no redirects, uses a maximum 2 MiB response and 16 KiB chunks, at most 256 market records, at most 4,096 levels per book side and a 300-second source-age gate. Each socket wait is at most three seconds; the default twelve-second elapsed deadline is checked between chunks, so expiry can exceed that deadline by one bounded socket wait. Injected clients may carry only standard public headers and no auth/query credentials; their context is rechecked before every GET. Response cookies are cleared before subsequent requests. The default client ignores environment proxy credentials. Archive directories must remain free of symlink components; existing content-addressed bodies are reused only if exact. This is an explicit trusted local archive destination, not a general worker filesystem capability.

The actual pinned replay is MLB game849844, Phillies at Braves. Current structured Polymarket and official MLB starts agree at 2026-10-02T00:00Z. The Polymarket description still says October1 at 2PM Eastern (18:00Z), six hours earlier. The adapter exposes `description_schedule_conflict`, retains the original rules, and blocks automatic comparison. Both official probable starters were absent in the captured schedule. Market data does not fill those missing sports features or bypass the existing starter guard.

Integration proposal: a separate reference-observation worker can call `PublicReferenceClient(explicit_archive)` and `observe_event(client, exact_event_id, validated_games)`, close the client and persist the returned diagnostic observation. Discovery may use the bounded series interface or exact event IDs, but must retain discovery errors and unmatched inventory. Keep this off the funding path until a separately reviewed exact settlement mapper, prospective calibration/blend validation, source freshness policy and independent reference-quality evaluation exist. One prediction exchange is not multi-bookmaker coverage and does not establish a sharp-book consensus. No production caller or configuration is changed by this component.

The new tests replay four complete original source bodies, exercise real contract/time disagreements, identity/fee/depth/schema/freshness failures, archive collisions and anonymous transport boundaries. `evidence/live-reference-result.json` records a fresh three-GET run of the pinned candidate. These are ingestion and diagnostic results, not model-promotion, profit or betting-availability acceptance.
