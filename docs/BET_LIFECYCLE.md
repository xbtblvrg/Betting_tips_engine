# Bet lifecycle tracking

The main **Bet Recommendations** list is treated as an execution list: funded recommendations and already tracked/marked bets appear there. Unfunded candidates remain in **Research / No bet recommended**, never alongside actionable picks without that distinction.

User-pasted accepted tickets can reconcile assumed entries through `Store.import_reported_bets`. The import preserves the original forecast and quote while storing reported accepted stake and odds, with before/after audit records. Explicit duplicate tickets remain separate monetary exposures. Replaying the same report does not duplicate them. Reported selections are checked off. Reported execution is user evidence, not a direct Stake account lookup. The 2026-09-28 report contains 17 tickets, 16 unique selections and a total stake of 17 USDT; Bears +6.5 appears twice. Nine prior assumed entries are reconciled, and eight additional tickets are recorded. Original quotes and user-reported odds are retained separately. Outcome-quality diagnostics count an identical selection once, while financial results include every ticket.

The personal placement checklist is separate from automatic tracking. Each exact selection has a reversible “Mark as placed” checkbox saved server-side in `placement_checklist`. Default order is unmarked picks by kickoff, followed by marked picks by kickoff. Repricing preserves the same selection's mark; a new line/selection ID starts unmarked. The state survives polling, restarts and device changes. Marking or unmarking never creates another ledger bet, changes bankroll exposure, or gates outcome learning. Automatically assumed bets start unmarked on this personal checklist.

The user's standing instruction is to assume every funded Stake recommendation is manually placed. `auto_track_recommendations` enables this; no per-pick confirmation is required. The installed service enables it from 2026-09-28. Fresh current picks enter on the next publication; older publications are not retroactively treated as executed bets.

Migration to exact-contract ownership uses `Store.migrate_contract_identity()` while the service is stopped, after a SQLite backup. It changes only the primary identity key in recommendation_issuance and system_decisions; timestamps, frozen decisions, tickets and checklist marks are preserved.

Publication and automatic ledger insertion share one SQLite transaction. Only fresh Stake recommendations with positive stakes, source evidence and matching odds qualify. Alternatives and watchlist picks do not qualify. Exact contract IDs, including already settled records, prevent duplicates after repricing. New qualified best lines and markets on an existing game are allowed under the latest user instruction. The old per-game cap is disabled; the $1–$5 per-bet limit remains. All configured limits are rechecked inside the transaction. Family selection still considers held contracts, so it does not rotate through inferior alternate lines merely to fill a quota. Request identifiers and source metadata survive service restarts. Already tracked picks remain visible with their original odds and stake in Open Tracked Bets and Bet Lifecycle Tracker, even if their current recommendation changes.

Each auto record stores `tracking_source=auto_assumed_placed`, `execution_verified=false`, `odds_basis=recommendation_snapshot`, the original model version/probability, recommended stake, line, observed odds and source evidence. These are user-authorized tracking assumptions, not a sportsbook receipt or a bet submission. The checkbox in Settings controls future automatic entries and does not erase existing records. The manually entered ledger remains available; the API rejects manually logging an already auto-tracked tip again.

On final sports scores, supported full-game contracts are evaluated using their frozen side and line: won, lost or push. Pending/live/postponed games without final scores remain open. A push refunds the stake. Settlement is idempotent and retains final score, source URL, source retrieval time and settlement time; it is not a confirmed Stake settlement. Exceptional bookmaker voids or different returned amounts still require a record correction rather than guessing from a score alone.

`bet_outcomes` stores selection-level results. On non-push outcomes, Brier and log loss use the original conditional win probability `p_win / (1-p_push)`; pushes have no binary score. Diagnostics are grouped by league, market and model version and shown in the tracker. They measure the selected portfolio, not unbiased population-wide calibration. Independent prospective game forecasts and the existing controlled daily model retraining continue; no outcome is an automatic instruction to change code, raise stakes or promote an unvalidated model.

Performance separates manually logged bets (`actual_bets`) from assumed bets (`assumed_bets`); `ledger_bets` contains the combined tracked ledger. Displayed combined P&L and cost-adjusted results include estimates based on recommendation odds and are labelled accordingly.
